Email-воронки после аудита

Письма с team@erythro.ai; флаг AUDIT_PRO_OFFER_ENABLED; на каждом языке (RU/EN/HE) — все три письма

Надёжность отправки
  • Статусы: scheduled → sent → nudge_sent → reminder_sent / skipped
  • PIT-123: атомарный claim pro_offer_lock_at — исключает дубли при гонке таймера воркера и Vercel cron
  • Сбой SMTP снимает lock; таймаут после DATA не ретраится
Платная ветка и приватность
  • Pro/Diagnostic оплачен → +15 мин письмо «Предложение о разработке» (правки по аудиту или пересборка)
  • Ссылка checkout защищена HMAC-токеном (id + срок 72 ч)
  • Отписка → таблица mail_unsubscribes

Инфраструктура и деплой

GitHub → Vercel (авто-деплой из main после CI) · VPS — отдельным скриптом

Vercel
  • Fluid Compute, регион iad1, Node 24
  • pnpm build = db:clear-dev-push → payload migrate → next build (код и миграции одним билдом)
  • Crons: /api/audit/reconcile (каждые 2 мин), /api/cron/sitemap-health (ежечасно)
  • БД: Supabase transaction pooler :6543, sslmode=no-verify
Hostinger VPS (Ubuntu 24.04, 8 ГБ)
  • Docker-сеть proxy_network: caddy_proxy, n8n (v2.41.7, pinned), audit_agent_worker
  • Публично за Caddy: n8n.erythro.ai, agent-api.erythro.ai (/health, /api/run-audit)
  • Порты контейнеров не публиковать на 0.0.0.0 (PIT-053)
  • Деплой: scripts/deploy_vps_audit_stack.py
Cloudflare
  • DNS + WAF + SSL Full (Strict), rate limit для форм
  • R2: медиа (CORS в infra/) и отчёты аудита
Резервирование
  • GitHub Actions: backup.yml (БД), keepalive-db.yml
  • Скрипты db:backup, db:ping; папка backups

Безопасность и качество

Многоуровневая защита; практики зафиксированы в docs/PITFALLS.md

Периметр
  • Cloudflare WAF + rate limit
  • Turnstile на формах и консультанте
  • Honeypot, санитайзинг, IP-лимиты (auditRateLimit, contactRateLimit)

  • Отчёт только с токеном k (иначе 404)

Данные
  • RLS как defense-in-depth (supabase-rls.md, PIT-110)
