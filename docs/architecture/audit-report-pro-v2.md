## 1. Что это

Современный вид отчётов по тарифам **Free**, **Diagnostic** и **Pro** (RU / EN / HE-RTL) в стиле Stape «Website Tracking Report», но в корпоративных цветах Erythro.ai.
Один HTML-файл на язык и тариф (стили инлайн, шрифты с Google Fonts), плюс печатный PDF A4.

### Разделение по тарифам:
- **Free (`free-{lang}.html/.pdf`)**:
  - Экспресс-аудит (1 URL — главная страница), 5 открытых базовых проверок чеклиста (23 проверки заблокированы с тизером).
  - Шкала скорости: 1/1. Воронка: статус по главной + тизер краула 10 страниц.
  - Рекомендуемые действия: Шаг 1 открыт полностью с кодом и copy, шаги 2–6 закрыты тизером с кнопкой перехода в Pro.
  - Решения в Топ-3 уязвимостях: скрыты строкой блокировки со ссылками на заказ Diagnostic и Pro.
  - AI Visibility: скрыты модели, факторы и вердикт; выведена тизерная карточка с кнопками перехода в Diagnostic (₪99) и Pro (₪390).
  - Навигация плашек шкал: бейджи шкал без действий в плане (SEO, и др.) скроллят к открытым проверкам в чеклисте (`#diag-seo`), а вне топ-5 — к карточке блокировки `#locked-checks`.
  - Футер: кнопки «Заказать Diagnostic · ₪99» и «Заказать Pro под ключ · ₪390», ссылки на заказ в тексте CTA.
- **Diagnostic (`diagnostic-{lang}.html/.pdf`)**:
  - Сводный аудит (5 URL воронки, 3 локали), все 28 проверок чеклиста открыты.
  - Все 6 шагов действий открыты в формате инженерных спецификаций ТЗ (`.spec-box`) вместо сырого кода, со ссылкой на Pro для внедрения под ключ.
  - AI Visibility и воронка открыты полностью.
  - Футер: кнопка «Улучшить до Pro за ₪390».
- **Pro (`pro-{lang}.html/.pdf`)**:
  - Полный аудит под ключ (10 URL воронки, 3 локали, 28 проверок, 84 проверки суммарно).
  - Все 6 шагов действий содержат готовые продакшн-сниппеты кода (`.code-box`) с кнопкой `.btn-copy`.
  - Футер: контакты и кнопка обсуждения в WhatsApp.

## 3. Главное: дизайн накатывает скрипт, а не ручная правка

Копии v2-HTML уже **дважды за вечер перезаписывали** другие агенты/процессы (весь дизайн пропадал). Поэтому вся полировка собрана в идемпотентный скрипт:

```bash
node services/audit-agent/QA_Auditor/scripts/apply-v2-polish.cjs       # накатить дизайн на все 15 копий
node services/audit-agent/QA_Auditor/scripts/render-v2-pdf.cjs         # собрать PDF (Playwright, @playwright/test из проекта)
```

Зеркальные копии скриптов: `C:\agents\website-auditor\erythro-ai\QA_Auditor\scripts\`.
Скрипт между маркерами `/* === v2-polish:start === */ … end` заменяет CSS-блок (новые запуски не копят стили), вычищает старые блоки `design polish …`, и применяет разметочные правки (каждая пропускается, если уже сделана):
- зелёные плашки шкал «Без замечаний» — без ссылки и стрелки;
- «P1 приоритет» → «Шаг N / Step N / שלב N» (+ легенда статусов и подзаголовок про порядок);
- сортировка «Рекомендуемых действий»: критично → требует внимания → остальные (внутри — канонический порядок speed, seo, lead, sec, ai), перенумерация;
- HE: выравнивание действий 4–6 с RU/EN (по id, не по позиции) + правки перевода (список `HE_TEXT_FIXES`, результат проверки воркером Translater);
- JS для печати (`matchMedia('print')`: снимает `name` у `<details>` и открывает все).

**Идемпотентность:** замена, чей результат содержит исходную фразу, применяется один раз (иначе «שיקוף» приклеивалось к заголовку при каждом запуске — PIT-131).

## 4. Дизайн-система (итог)

- **Палитра:** body `#eaeaea`, секции `#f8f8f8`, линии `#d6d6d6`, muted `#554f42`, ink `#1e1e1e`, бренд `#e52421`, зелёный `#22bf16`, оранжевый `#ff7900` (в «Шаг» — `#e8650a`, чтобы белая цифра читалась), серый «рост» `#6b6b6b`, золото `#ffe9c7` (плашка в шапке). Фиолетовый — только блок AI Visibility.
- **Статус везде один:** красный = критично, оранжевый = требует внимания, зелёный = отлично, серый = точка роста.
- **Шрифты:** RU/EN — Inter (все бейджи тоже, моно убран); HE — Heebo везде. Код — IBM Plex Mono (в HE: `'IBM Plex Mono','Heebo'`, строки кода всегда LTR).
- **Отступы:** переменная `--pad` (60px desktop, 32px планшет, 22px телефон); зазор секций 40px; логотип подтянут к плашкам (`margin-bottom:-30px`).
- **Аккордеон чеклиста:** плавное раскрытие (`::details-content`), цветная полоска 3px слева, шеврон по центру круга (CSS-стрелка, текстовый «⌄» скрыт `font-size:0` + `font-size-adjust:none`), hover: тень `0 0 5px rgba(0,0,0,.1)` и белый фон (в покое `#f8f8f8`).
- **Рекомендуемые действия:** белые карточки, цвет только у полоски 3px и плашки «Шаг N», hover-тень `0 0 20px rgba(0,0,0,.2)`, блок кода и кнопка copy — в цвет статуса; легенда статусов.
- **Топ-3:** красная плашка с цифрой (радиус 5px, высота = высота шапки карточки), красный верх у всех трёх.
- **Мобильная версия (≤600px):** шкалы в одну колонку, код переносится, плашки/кнопки по тексту.
- **HE:** `dir="rtl"`, кольцо зеркальное, цифра оценки справа, `font-size-adjust:.55` под Heebo.

## 5. PDF: как собирается и подводные камни

Скрипт `render-v2-pdf.cjs`: Playwright, `emulateMedia(print)`, все `<details>` открыты, `printBackground`, **`@page{margin:0}`**, поля 10мм/8мм воссозданы обёрткой-таблицей (`thead`/`tfoot` повторяются на каждой странице) — иначе белые поля не закрашиваются фоном `#eaeaea`. Итог: RU/EN/HE ≈ 20 страниц.

Правила печатного CSS (в блоке `@media print` скрипта):
- Короткие секции (шкалы, технологии, таблица, «Путь к заявке», протокол, AI Visibility) — целиком (`break-inside:avoid`); первая страница = шапка + общая оценка + результаты диагностики.
- Длинные секции (топ-3, действия, чеклист) — **без общей рамки**; карточки-пункты не рвутся. Топ-3 начинается с новой страницы, три карточки занимают её (`min-height:71mm` каждая).
- Кнопка «Заказать свой аудит» — перед блоком консультации, футер по центру; шевроны и ссылки «Смотреть решение…» в PDF скрыты; код переносится, шрифт 10px.
- Если целевой PDF занят просмотрщиком (Windows lock), скрипт кладёт свежий файл рядом как `*.new.pdf`.

Просмотр PDF без poppler: открыть PDF через pdf.js (cdn.jsdelivr `pdfjs-dist@4.0.379`) в Playwright и снимать canvas.

## 7. Известные расхождения (не исправлены, это содержимое генератора)

1. В RU/EN шаг «AI-квалификация входящих заявок» стоит с кодом Turnstile/honeypot — текст и код не совпадают по смыслу.
2. `id="action-speed"` повторяется у шагов 1 и 2 (якорь ведёт на первый).
3. В чеклисте нет критичных пунктов, а топ-3 и шаг 1 называют скорость «Критично»; у шкалы скорости (50) нет соответствующего пункта в чеклисте.
4. Бейджи шкал показывают «Есть замечания / Без замечаний», а не точное число замечаний.
