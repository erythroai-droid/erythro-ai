### 1. Общие требования и Стек

- **Стек:** Next.js (App Router), Tailwind CSS, TypeScript, GSAP (ScrollTrigger).
    
- **Назначение:** Главный технический регламент для ИИ по сборке клиентской части Next.js. Данный файл координирует правила чистой верстки, семантику тем и логику мультиязычности, исключая галлюцинации и обеспечивая продакшен-качество кода.
    
- **Именование компонентов:** Строгое использование семантических понятных имен (например, `Navbar`, `MenuLight`, `MenuDark`, `ButtonDark`, `BrandLogo`). Запрещены случайные hardcoded-значения и сторонние отступы — всё пишется строго через расширения тем.

### 4. Правила локализации и RTL-поддержки (EN, RU, HE)

Сайт является полностью мультиязычным. При верстке интерфейса ИИ обязан строго следовать двум законам локализации:

#### Закон 1: Стресс-тест длины текста (+40%)

- Русский текст длиннее английского аналога в среднем на 40%.
    
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать фиксированную ширину для интерактивных элементов (`w-[180px]`), кнопок, табов и элементов навигации.
    
- Используй только утилиты Auto Layout поведения: `flex-1`, `w-full`, `max-w-*` и `gap-*`. Контейнеры обязаны динамически растягиваться и подстраиваться под контент.
    

#### Закон 2: Логические свойства вместо направленных (RTL-готовность)

- Для поддержки иврита (`dir="rtl"`) раскладка должна зеркалироваться автоматически на уровне движка стилей.
    
- Настраивай Middleware в Next.js на подстановку динамического атрибута направления в корневой тег: `<html dir={currentLocale === 'he' ? 'rtl' : 'ltr'}>`.
    
- При переключении на локаль `he` (иврит) для всего контента в обязательном порядке применяется системный и полностью поддерживающий RTL шрифт **Inter**.
    
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать направленные классы Tailwind: `pl-`, `pr-`, `ml-`, `mr-`, `left-`, `right-`.
    
- **ОБЯЗАТЕЛЬНО** использовать логические альтернативы:
    
    - `ps-*` (padding-start) вместо `pl-*` / `pr-*`
        
    - `pe-*` (padding-end) вместо `pr-*` / `pl-*`
        
    - `ms-*` (margin-start) вместо `ml-*`
        
    - `me-*` (margin-end) вместо `mr-*`
        
    - `start-*` / `end-*` вместо `left-*` / `right-*`
        
- Иконки стрелок, указывающие направление (например, `➔`), при `html[dir="rtl"]` должны разворачиваться в противоположную сторону с помощью класса `rtl:rotate-180`.
    

### 5. Инструкции по поблочной сборке UI

1. **Изоляция модулей:** Все интерфейсные блоки (Шапка, Hero-блок, Лента партнеров) должны разрабатываться как изолированные, строго типизированные (TypeScript) компоненты, использующие семантические классы стилей (`bg-surface`, `text-main`).
    
2. **Правило плавности (Плавные переходы):** Любые интерактивные состояния (`hover:`, `focus:`, `active:`) на кнопках, ссылках, пунктах меню или элементах навигации обязаны иметь плавную анимацию переходов. Обязательно добавлять класс `transition-all duration-300`.
    
3. **Адаптивная сетка (1170px):** Адаптив строится на базе брейкпоинтов Tailwind, обеспечивая идеальный вид на любых экранах. Ограничитель десктопного контента `max-w-content-grid` (1170px) использует 12-колоночную разметку:
    
    - `grid grid-cols-12`
        
    - Ширина колонки: `70px`
        
    - Расстояние между колонками: `gap-30px` (или `gap-space-30px`)
        
    - Внешние поля макета: `px-space-30px`
        
4. **Мобильные оверлеи (Mobile_Menu_Overlay):** При падении разрешения экрана ниже контрольной точки `lg` (1024px) горизонтальное меню скрывается, уступая место кнопке-бургеру. Выплывающее меню реализуется как наложение (Overlay), выезжающее со стороны `end` (справа для EN/RU, слева для HE). Фон оверлея обязан использовать `bg-coal-900/80` с обязательным премиальным эффектом размытия заднего плана `backdrop-blur-md`.
